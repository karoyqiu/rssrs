# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.
If these files do not exist, proceed silently. Create them lazily through
`domain-modeling` when terminology or decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, tests, and code.
If a needed concept is missing, reconsider the terminology or record
the gap for `domain-modeling`.

## Decisions

Explicitly identify any proposal that contradicts an existing ADR,
and explain why the decision should be reconsidered.
